# 현재 작업 기반 완료 보고 게이트 · 2026-10-15

광고 비교에서 OMC는 CONTRACT·RED를 본문에 작성했지만 등록하지 않았고, 브라우저 미실행을 적으면서 완료를 선언했다. 비교 원본은 `ad-ui-native-pair-20261015.md`에 보존한다.

이번 변경은 `omc_pipeline_guard.py complete-task`로 최종 상태 문장과 기계 판정을 함께 생성한다. CONTRACT에 필수 검증 ID를 고정하고, 같은 confirmed session의 계약·RED 등록과 검증 레코드를 대조한다. 미등록, 다른 작업의 기록, 필수 검증 누락·미실행·빈 근거는 완료로 출력하지 않는다. 실패와 증거 불일치는 각각 다른 상태 문장으로 출력한다. 계약 최초 등록 당시의 미스테이징·미추적 구현 변경을 내용과 권한 지문으로 보존한다. 그대로인 기존 변경은 완료를 막지 않는다. 새 변경이나 기존 파일의 추가 변경은 미스테이징 상태에서 완료를 막는다. 같은 세션의 계약 재등록은 이 기준을 덮어쓰지 않는다.

## 사용

1. `contract-done --required-checks tests,lint,browser`로 필요한 검증 목록을 고정한다. 브라우저 불필요 작업은 계약에서 해당 ID를 제외한다.
2. 실제 실패를 확인하고 `red-done <테스트파일>`을 등록한다.
3. `verification-path`가 제공하는 내부 경로에만 검증 JSON을 작성한다. 검증 JSON에 현재 `session_id`, `checks`를 기록한다. 각 ID는 `status`와 비어 있지 않은 `evidence` 문자열을 갖는다. `implementation`에도 `status: applied`와 비어 있지 않은 `evidence`를 기록한다. 구현 반영 근거가 없으면 `구현 여부 확인 불가·검증 미완료`로 차단한다.
4. `complete-task --verification-file <JSON>`의 상태 문장·기계 판정을 그대로 최종 보고에 사용한다. 차단 시 종료 코드는 1, 통과 시 0이다.

예: 테스트·린트 통과, 필수 브라우저 미실행 → `구현됨·검증 미완료`, `outcome=blocked`, `VERDICT: BLOCK`.

## 검증과 한계

직접 CLI를 실행하는 회귀 테스트로 미등록·과거 RED·다른 작업 검증·필수 브라우저 누락·빈 근거·실패·증거 불일치·미스테이징 변경·미추적 구현·정상 통과를 확인한다. 내부 상태 검사만으로 사용자 표시 문구 검증을 대신하지 않는다.

검증 레코드는 호출자가 제공한 선언이다. 근거 문자열의 진위, 테스트·브라우저 실제 실행은 이 명령이 인증하지 않는다. 이 명령을 생략하거나 자유 응답으로 우회하는 모델을 물리적으로 차단하지 않는다. 기존 파일 편집 훅의 우회 경로를 이번 변경에서 전면 재설계하지 않았다. 자동 실행 소비 경로 전부에 강제 연결하거나 모델 준수율이 개선됐다고 주장하지 않는다.

Claude·Codex task 템플릿에 호출 절차를 연결하고 현재 저장소의 task 안내 복사본만 동기화했다. 정상 사용처 재설치·릴리스·새 모델 재비교는 실행하지 않았다. 코드 리뷰는 별도로 필요하다.

리뷰 후 보완: 무관한 기존 변경을 유지하는 tracked/untracked 사례, 그 파일을 추가 변경한 사례, 동일 세션 계약 재등록, 구현 반영 근거 누락·불명·빈 문자열을 실제 CLI로 검증한다. 기존 변경을 stash·삭제·강제 스테이징하지 않는다.

후속 보완과 실제 모델의 재비교 보류 결과: [최종 원문·경로 검증](workflow-boundary-validation-20261015.md).
