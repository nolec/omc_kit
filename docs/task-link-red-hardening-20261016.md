# 정상 폴더 링크·요구별 RED 근거 보완 — 2026-10-16

## 반영한 동작

- 내부 폴더 심볼릭 링크를 링크 문자열·내부 대상·폴더 권한·검사 대상 파일의 목록/내용/권한에 연결한다. 정렬된 입력의 반복 스냅샷은 동일하며 대상 수정·추가·삭제·이름/권한 변경·링크 대상 변경은 이전 완료 증거를 거부한다.
- 경로의 각 링크 해석 단계에서 저장소 밖 진입을 거부한다. 외부를 거쳐 내부로 돌아오는 링크·끊김·순환·64회 초과·검사 제외 대상도 거부한다. 외부 파일 내용 미읽기 회귀를 포함한다. 일반 Git ignored 파일과 Git 없는 환경의 의존성·캐시 제외 경계는 유지한다.
- 새 승인 CONTRACT의 RED는 `--evidence-file`로 승인 검증 ID·실패 케이스·기존 실패 목록·실제 출력·파일 해시를 기록해야 한다. 기존 실패 목록에 있던 케이스만으로는 등록하지 않는다. 현재 종료 코드1과 새 실패 케이스가 필요하다.
- 등록 뒤 JSON/출력 변경·승인 개정 불일치는 완료 명령과 공유 판정/수집기에서도 거부한다. 테스트 리팩터링 후에는 과거 RED 원문을 현재 FAIL로 다시 쓰지 않고 보존한다.
- 실행 안내는 빠른 가이드52줄과 상세 참고 문서로 나눴다. 원본 템플릿과 이 저장소의 설치 복사본을 동기화했다. 기존 가이드의 비어 있지 않은 줄 수71줄은55줄 제한을 이미 초과했으며 제한을 늘리지 않고 상세를 분리했다.

## 검증

실제 공개 CLI를 먼저 실행해 초기 회귀22개 중16실패·6통과를 확인하고 등록했다. 변경 전 CLI를 보존한 격리 재실행에서도 같은16실패·종료1을 확인했다. 수집기가 변경된 RED 기록을 믿고 이전 done을 수용하지 않는 표면 회귀를 추가해 신규24개 모두 통과했다. 전체 관련 회귀250개 통과, Python 컴파일·diff 공백 검사·staged TDD 게이트 통과. 전체 프로젝트 게이트·모델 재실행은 이번 검증이 아니다.

T4는 이전 광고 후보를 보존한 복사본에서 수행했다. 새 폴더 링크 회귀 자체의 변경 전 CLI RED(종료1)→현재 CLI GREEN(종료0)을 실제로 실행하고 새 세션에 근거를 연결했다. 과거 광고 기능의 무관한 RED는 소급 인증하지 않았다. 별도 프로세스로 현재 원본 가드를 호출했으며 일반 사용처 설치본을 교체한 검증은 아니다.

복사본과 기존 검수 서버의 코드·권한·링크 전체 스냅샷이 같음을 확인한 뒤 통제6종 화면과 실제 홈을 새로 관찰했다. 이미지2개 로드·테두리/그림자·화살표0·시간차 자동 전환 확인. Ad 테스트41통과·기존4실패의 이름과 actual/expected 동일, ESLint 종료0. 클릭 추적·숨김의 실제 이벤트 전송은 여전히 미검증이며 통과로 승격하지 않는다.

완료 CLI는 PROCEED/done, 수집기 필수6항목·서식3항목 통과/allow다. 이 수집 입력은 실제 CLI 호출·출력을 수집기 형식으로 감싼 조정자 기록이며 native Claude 응답이 아니다. 첫 포맷은 종료 메타데이터 누락으로 hold였고 원본을 보존했다. 실제 종료0을 다시 캡처한 별도 포맷으로 재수집했으며 광고/제품 코드를 고쳐 수집 결과를 구제하지 않았다.

최종 대조에서 legacy RED 파일명 목록이 새 근거 등록에 섞이는 경로를 발견했다. 실제 CLI 회귀1실패 후, 근거 receipt가 있는 테스트만 새 등록으로 승격하도록 수정했다. 이때 등록 성공 안내가 이미 등록됨으로 출력돼 수집기의 procedure_calls가 unknown이 되는 표면 문제도 정상 완료→변조 거부 회귀로 재현해 수정했다. 두 추가 실패 원문과 수정 전 hold 판정은 보존했고, 최종 현재 CLI 수집6항목 모두 통과했다.
