# 광고 UI 동일 조건 재비교 · 2026-10-15

## 결론

이번 한 사례에서는 OMC 후보의 UI 결과가 더 좋았다. OMC는 10분 22초에 종료됐고 실제 홈과 6개 통제 광고 화면에서 테두리·그림자·화살표 제거·자동 전환을 확인했다. oh-my-claudecode는 20분 제한 시간에 종료돼 최종 보고가 없었으며, 남은 코드의 테두리가 불투명 이미지에 가려졌다.

그러나 OMC도 전체 완료 판정은 부정확했다. 필수 브라우저 검증을 실행하지 않았다고 쓰면서 ‘필수 검증 통과·작업 완료’라고 보고했다. CONTRACT·RED를 본문으로 설명하고 테스트를 먼저 바꾼 실행 흔적은 있으나, pipeline 상태의 contract_confirmed=false, red_done_tests=[]가 유지됐다. 절차 안내와 등록·완료 판정의 연결을 보완해야 한다.

이 결과는 단일 탐색 사례이며 OMC의 일반적 우위나 절차의 인과적 효과를 입증하지 않는다. 이번 후보를 원본 서비스에 반영하거나 커밋·배포하지 않았다.

## 같은 조건

- 제품 기준 코드: `34078b6f923587b03c0fbac3d7a5a3c4bf5c0cfc`, 각각 새 복사본 사용.
- 같은 Sonnet 4.6 Bedrock 모델, high effort, 도구별 1,200초 제한. 이번 순서는 경쟁 도구 → OMC.
- 동일 task.md, 저장된 디자인 설명·이미지, 같은 고정 의존성. 명시적 진입 문자열 `/oh-my-claudecode:execute`, `/task` 사용.
- 실제 Home의 카드 한 곳에 같은 임시 광고 2개를 items로 공급했다. 운영 CMS 광고는 수정하지 않았으며 이 공통 준비 변경의 해시는 양쪽 모두 실행 후 동일했다.
- 최초 실행은 설정 파일 접근 제한으로 0토큰 상태에서 종료했다. 구현 실패에 합산하지 않고 별도 보존 후 권한을 확보해 재시도했다.
- OMC 설치 파일 무결성 확인은 통과했지만 중앙 설치 레지스트리 기록은 파일 권한으로 실패했다. 정상 사용처 설치나 릴리스로 취급하지 않는다.

기준 코드부터 있던 추적 관련 4개 실패 이름을 보존했다. 후보가 자신의 테스트를 수정해 테스트 개수와 기대값이 달라지므로 통과 개수만으로 우위를 판정하지 않았다. 같은 외부 화면 구성과 기준 실패 이름으로 별도 대조했다. 통제 화면의 500ms 관측과 3,700ms 관측 사이에 6개 트랙이 모두 이동했다. 이는 엄밀한 실시간 3,000ms 정밀도 측정이나 모든 서비스 동작 검증을 뜻하지 않는다.

OMC 이벤트에는 테스트 수정 → 실패 검사 → 제품 수정 → 재검사 → 추가 수정 → 재검사 순서가 있다. 가드의 staged 검사는 스테이징된 변경이 없어 신규 구현 없음으로 통과했으므로 이를 제품 전체 게이트 통과로 승격하지 않는다. 두 후보의 정규화된 재작업 횟수는 아직 산정하지 않았으며 도구 호출 수로 대신하지 않는다.

## 실제 홈 검수와 남은 경계

같은 임시 포트 localhost:3011에서 후보 서버를 순서대로 실행했다. 서버 전환 후 초기 로딩 지연과 로그인 화면 이동을 관측했고 사용자가 한 번 재로그인했다. 이후 OMC와 경쟁 후보 모두 실제 홈 카드·배너와 자동 전환을 확인했다. 기존 localhost:3000 서버는 변경하지 않았다. 이 로그인 개입은 모델 실행 단계 밖의 검수 준비 비용이다.

카드 데이터는 통제된 임시 items이므로 운영 카드 CMS 연결·광고 추적을 입증하지 않는다. 준비 단계의 임시 링크 클릭은 새 탭을 열었지만 로그인으로 이동해 목적지 확인은 미완료다. 운영 배너 클릭·오늘 하루 숨김도 이번 독립 브라우저 검사에서 실행하지 않았다. 서명된 완료 관측이나 사용자의 블라인드 사용성 채점으로 취급하지 않는다.

명시적 명령 문자열과 등록 목록만으로 도구 고유 절차가 완전히 소비됐다고 단정하지 않는다. 실제 확인한 도구 호출 순서·등록 상태·최종 보고를 근거로 절차 적용 정도를 제한해 판단한다.
