# OMC QA

수동 QA 체크리스트 전용입니다. 구현 후 사용자 검증을 돕는 목적이며 코드 리뷰를 하지 않습니다. 배포 게이트를 대신하지 않습니다.

```bash
git diff --stat HEAD 2>/dev/null | head -20
python3 scripts/omc.py state status --target .
```

- diff 또는 plan이 없고 입력 부족이면 `고정 QA 생성 불가`로 멈춥니다. 기존 검증 결과가 없어도 후보는 만들되 `근거 없음`으로 표시합니다.
- 사용자에게 보여줄 것: 기존 검증과 중복 / 추가 확인 / 미실행 또는 실행 결과 / 다음 추천
- 시스템이 암묵적으로 처리: 변경 범위 읽기 / 화면·역할 추론 / 근거와 범위 대조 / 중복 항목 제거

## 입력 계약

- 변경 기능:
- 영향 화면/흐름:
- 사용자 유형:
- 확인 환경:
- 기존 검증 결과: 실행한 명령·결과, 화면·환경·대상, 근거와 미확인 사항. 사용자가 제공한 결과와 직접 확인한 결과를 구분합니다.

## 출력

- 각 후보를 `이미 확인` 또는 `추가 확인 필요`로 분류하고, 기존 검증 근거가 없으면 추가 확인에 `근거 없음`을 함께 표시합니다. 대상·시점·환경·행동·결과가 일치하는 근거만 이미 확인으로 보고 부분 일치는 남은 차이를 추가 확인으로 씁니다. 실패와 미실행을 통과로 바꾸지 않습니다.
- 정상 흐름 / 예외 흐름 / 회귀 포인트에서 해당하는 것만 선택하고, 우선순위 높은 QA 5개 이내를 기본으로 필요한 만큼 제시하고, 위험상 더 필요하면 이유와 추가 항목을 씁니다. 각 항목에 검증 환경 / 조작 / 기대 결과 / 기존 근거와 차이를 씁니다.
- 목록만 요청했으면 `실행 결과 아님`을 명시하고 결과를 추정하지 않습니다. 사용자가 명시적으로 검증 실행을 요청했거나 현재 요청에 실행이 포함된 경우에만 허용된 범위에서 실행합니다.
- 실행 시 각 항목에 통과 / 실패 / 미실행, 실제 검증 환경, 실행 근거, 실행 주체·시점·출처, 관찰과 한계를 씁니다. 과거 확인과 이번 실행을 분리합니다. 실행하지 못하면 이유를 씁니다. 사용자 제공 결과를 직접 관찰한 것처럼 쓰지 않습니다.
- 컴포넌트 단독 / 실제 호스트 코드와 모의 API / 배포된 서비스를 구분하고 미확인 환경으로 결과를 확대하지 않습니다.

## 경계

- `omc-plan`의 구현 전 테스트 설계를 가져오지 않습니다.
- `omc-review`의 코드 리스크 검토를 가져오지 않습니다.
- `omc-ship`의 배포 승인/게이트를 가져오지 않습니다.

## 다음 추천

- 주추천 1개: 구현 후 검수면 `$omc-review`, 배포 직전 최종 점검이면 `$omc-ship`
- 구현 전이거나 입력 부족이면 `$omc-plan`
- 자동으로 진행하지는 않습니다.
